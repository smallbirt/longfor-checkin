# 每日签到

本仓库包含 Python 后端、Web 前端和微信小程序完整源码。

| 目录 | 内容 |
| --- | --- |
| `app/` | Flask 后端、API、计划任务、存储和通知 |
| `app/templates/`、`app/static/` | Web 前端、管理后台、使用手册与视频资源 |
| `miniapp/` | 可独立安装和构建的 Taro + React 微信小程序 |
| `prototype-admin/`、`prototype-miniapp/` | 独立的静态交互原型 |
| `tests/`、`scripts/` | 后端测试与运行、迁移、预览脚本 |

后端启动见下方「快速启动」；小程序安装、编译及联调见 [miniapp/README.md](miniapp/README.md)。部署说明中的绝对路径、服务器地址和历史运行结果是原环境记录，迁移时请使用自己的配置。本地 `.env`、数据库、密钥、HAR、依赖和部署产物不纳入版本管理。

操作视频按要求保留在本地，不上传 GitHub。需要视频功能时，将自己的视频放在 `app/static/tutorial/checkin-tutorial.mp4`；教学封面和图文手册仍包含在仓库中。

## 已实现

- 用户自行注册、用户名和密码登录；密码使用带盐 PBKDF2-SHA256（600,000 次）哈希。普通用户可修改自己的密码，管理员可通过 CLI 重置普通用户密码，修改后旧会话失效。
- 旧版凭证、发信配置、原收件邮箱和记录保留在 `admin` 账号。新用户从空白配置开始，不能读取或修改其他人的数据。
- 首页保留计划、两端状态与最近 5 条运行记录；独立登录凭证、通知与账号、分页记录页面。管理员另有平台设置页。
- 普通用户只填写自己的收件邮箱并验证，不需要邮箱密码。QQ／163 发件邮箱与 SMTP 授权码由管理员统一配置，仅管理员可访问。

- 默认以北京时间 **09:10** 签到、**16:00** 复核为中心；每个账号、每个时段每天在设定时间前后 30 分钟内随机安排，未签到时复核可补签。靠近午夜或两个时段接近时随机范围会缩小；服务离线或任务繁忙时可能延迟。默认暂停，完成配置后手动开启。
- App 与小程序保留各自的活动编号、渠道、账号与签到设备信息。App 短信仅更新 App；小程序单独导入，文件即使含两端记录，也只保存页面所选渠道。
- 每轮发送一封两端汇总邮件，包含成功、登录失效、验证码、网络异常等结果。单个渠道失败不会中断另一渠道。
- 查询当日日历 `sign_status`，只有 `20` 判为已签到、`10` 判为未签到。缺少当天记录、未知响应或复核失败都不会报告成功。
- 登录凭证页支持 App／小程序成功登录 HAR（含响应），新 token 先通过只读状态查询再保存；个人或平台 App 登录设备齐全后可尝试网页短信更新 App。
- 龙湖账号页按渠道上传一份 HAR，自动合并登录与设备记录。兼容旧签到页状态查询包；解析器独立选择最新登录凭证和最新实际签到设备，导入只验证状态，不立即签到。旧文本／JSON／cURL 解析和设备接口保留兼容，但页面不再提供独立入口。
- 邮箱通知采用持久化队列，失败按 1 分钟、5 分钟、30 分钟间隔重试，最多 4 次；失败后可手动重试。发信失败不会重新签到。
- 遇到滑块时，每个渠道每轮获取并验证一道新题；通过后携带临时凭证继续签到并查询确认。旧的“需要验证”标记也能自动恢复，登录失效仍需更新登录凭证。

## 接入 HR 的 PostgreSQL

服务器使用现有 HR PG 实例中的独立 `longfor_checkin` 库和专用非超级用户。完整自动接入与备份流程见 [PG-DEPLOY.md](PG-DEPLOY.md)，接入脚本为 `scripts/connect_pg.py`。脚本会先备份原数据、构建、校验、离线迁移并逐行核对，再仅切换签到容器。原管理员账号、各用户凭证、邮箱和运行记录会保留。

启用 PostgreSQL 后，原数据卷仍需保存加密密钥。备份要同时包含 PG dump 与整个 `/data`，不能只保存数据库或删除原卷。`DATABASE_URL` 为空时继续使用 SQLite；已有 SQLite 时，不能仅填 URL 直接启动，应先执行迁移流程。

## 快速启动（本地 SQLite）

需要 Docker Engine 与 Compose 插件。项目需单实例运行，不要扩容或使用多进程 worker。

```sh
python3 manage.py setup
docker compose up -d --build
```

打开 `http://127.0.0.1:8091`，管理员用户名为 `admin`，密码为项目 `.env` 文件中的 `ADMIN_PASSWORD`。旧版升级见 [UPGRADE.md](UPGRADE.md)。

1. 管理员在「平台设置」配置 QQ 或 163 发件邮箱及 SMTP 授权码。已有配置自动沿用。
2. 普通用户通过注册页面创建自己的本站账号。注册默认开放，管理员可关闭；当前限制最多 100 个账号，适合小规模使用。
3. 在「通知与账号」填写自己的邮箱，收取 6 位验证码并验证。验证码 10 分钟有效、最多尝试 5 次；发送设有频率限制。原管理员的收件邮箱无需重复验证。
4. 管理员导入的设备自动作为平台配置。普通用户在「我的签到」添加 App／小程序账号，每个账号导入自己的 HAR，登录与设备自动合并；设备齐全时无需再抓签到记录。之后点击「更新登录」修改，App 可尝试短信续登；个人设备自动优先。
5. 发送测试通知，确认后进入各个签到账号，设置独立的签到、复核时间与开关。新添加账号默认暂停。
6. 开启时若已过今天计划时间，会按该账号自己的时间补执行当天最近一轮；默认 09:10 签到、16:00 复核与补签。不追补历史日期，也不重复已完成的当日时段。


2026-10-19 已实际验证 App 自动滑块、携带新凭证签到和查询确认的完整流程。历史验证码凭证不会保存或重放。服务端策略可能变化，失败时仍需手机处理，不能保证长期成功率。旧版升级见 [UPGRADE.md](UPGRADE.md)。

### 服务器或 NAS 访问

默认仅监听宿主机回环地址。服务器上部署后可使用 SSH 隧道访问：

```sh
ssh -L 8091:127.0.0.1:8091 用户名@服务器地址
```

然后在本机浏览器打开上面的地址。若使用可信局域网，可在 `.env` 修改 `BIND_ADDRESS` 为宿主机局域网 IP 后重建容器。远程公网访问请放在 HTTPS 反向代理后，并设置 `COOKIE_SECURE=true`，不要直接把 HTTP 管理端口暴露到公网。

## QQ 和 163 邮箱

### 构建时 Docker Hub 连接失败

只切换本项目的基础镜像，不修改全局 Docker 配置或重启 Docker。先确认服务器能够拉取 Docker 官方在 ECR Public 发布的镜像：

```sh
docker pull public.ecr.aws/docker/library/python:3.12-slim
docker compose -p longfor-checkin build --build-arg PYTHON_BASE_IMAGE=public.ecr.aws/docker/library/python:3.12-slim
```

此参数仅对当前构建有效，后续重新构建时也需要传入；构建成功后使用 `docker compose -p longfor-checkin up -d` 启动已有镜像。若 ECR 同样不可达，需要另行准备与云服务器 CPU 架构一致的离线镜像。首次迁移仍须先恢复数据再启动。

### 发信配置

| 服务 | SMTP 主机 | 端口 | 加密 | 密码字段 |
|---|---|---|---|---|
| QQ 个人邮箱 | smtp.qq.com | 465 | SSL/TLS，验证证书 | SMTP 授权码 |
| 163 个人邮箱 | smtp.163.com | 465 | SSL/TLS，验证证书 | 客户端授权码 |

平台发件目前仅支持 `@qq.com` 与 `@163.com` 发件地址，不支持腾讯企业邮、网易企业邮或 QQ 别名发件。收件地址不限这两家，可与发件地址相同。平台配置一个发件账户，每个用户配置一个独立收件地址。所有通知共用该发件账户的额度，是否接收由邮箱服务商决定。

QQ 网页邮箱：头像 → 设置 → 账号与安全 → 安全设置，开启第三方协议服务并生成授权码。参考 [QQ 官方授权码说明](https://help.mail.qq.com/detail/106/985)。

163 网页邮箱：在设置中找到 POP3/SMTP/IMAP 服务，开启 SMTP 并按提示生成客户端授权码；以实际后台为准。参见 [网易邮箱帮助中心](https://help.mail.163.com/)。

保存配置不发送邮件；「发送测试邮件」使用已保存配置。更换发件账号或服务商时必须重新填写授权码，同一账号留空保留原授权码。SMTP 服务器接受邮件不等于进入收件箱，仍可能被归入垃圾邮件或延迟投递。

## 登录失效与验证码

- 登录失效：手机 App／小程序重新登录，捕获包含成功响应的 HAR，在对应渠道点击「更新登录」。没有新设备记录会沿用原配置或平台设备，页面不显示已保存的明文凭证。
- 需要验证码：自动尝试一次；失败则停止本轮提交并发送结果邮件。也可在手机完成签到后点击「查询状态」。下轮任务可再次尝试自动验证，确认已签到后会清除旧验证标记；其他渠道继续运行。
- 不保存 `X-LF-DXRisk-Captcha-Token`，它是短期验证凭证，不能当作长期登录凭证。
- 不自动刷新设备指纹或续期登录 token；目前复用用户各自导入的凭证，有效期取决于服务端。抓包中的 `expire=2592000` 未验证单位，不据此保证 30 天有效。
- 扫码登录、小程序网页原生短信登录及手机自动同步尚未实现。App 网页短信已接入，实际可用性取决于服务端设备校验；早期方案评估见 [LOGIN-OPTIONS.md](LOGIN-OPTIONS.md)。

兼容解析器支持多行 `Header: value`、JSON 请求头对象、`{"headers": {...}, "body": {"activity_no": "..."}}` 及包含 `-H`、`--data-raw` 的 cURL。只解析文本，绝不执行 shell。当前活动限定为抓包确认的两项；若活动变更需要更新 `app/constants.py` 并重新验证。

## 数据、运行与维护

凭证和邮箱配置使用 Fernet 加密保存在 Docker 的 `checkin-data` 命名卷中。SQLite 模式下，管理员沿用卷根目录数据库，新用户位于 `users/<用户编号>/`；PG 模式下，使用 `checkin_u<用户编号>` schema，账号与平台设置在 `checkin_u1`。两种模式都使用原数据卷内的独立加密密钥。备份应复制整个数据卷，包含全部 users 子目录。密钥同存于卷内，作用是防止数据库文件单独泄露时直接暴露凭证，不能防护拿到整卷或主机权限的人。备份时需同时保留数据库和 `secret.key`；不要提交 `.env`、数据卷或原始 HAR 到代码仓库。

运行记录和邮件队列持久保存，不包含原始请求或 token。容器重启后同一天同一时段不会重复执行；中断的定时任务会重新查询服务端后继续。不要把已启用计划的数据卷克隆成多个同时运行的实例。

签到 POST 超时不重试，只查询确认。明确返回需验证码的业务码时，允许完成一次新验证，再复查状态并携带凭证提交一次；仍被拒绝时停止。下午任务和手动任务也始终先查状态。服务器关机期间无法发送提醒，启动后只补做当天最近一轮。运行记录长期保存，个人低频使用通常体积很小。

```sh
docker compose logs --tail=50
docker compose down            # 保留数据卷
# docker compose down -v 会删除凭证和全部记录，请不要误用
```

管理员密码可通过修改 `.env` 的 `ADMIN_PASSWORD`（至少 16 位）再执行 `docker compose up -d` 重设；旧登录会话随之失效。

## 开发验证

建议 Python 3.12；PostgreSQL 驱动需要 Python 3.10 及以上。Docker 已使用 Python 3.12。

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

测试使用模拟的龙湖接口和 SMTP，不会实际签到或发送邮件。覆盖重复签到保护、响应复核、验证码、凭证失效、跨天计划、重启去重、导入隔离、凭证加密、CSRF 和 QQ／163 发信配置。

验证码模块基于 MIT 许可的 [CheerfulChen/longfor-sign](https://github.com/CheerfulChen/longfor-sign) 固定版本修正，来源及许可证位于 `app/vendor/longfor_captcha/`。图片识别使用 OpenCV headless，不需浏览器或外部识别平台；验证图片临时存放于 `/tmp`，完成或异常退出时删除。

可选本地运行：`python manage.py serve`，在单独的 `data/` 目录保存本地数据。Docker 和本地运行的数据互不共享；不要同时启用两套每日计划。

## 普通用户密码重置

管理员在服务器的项目目录执行以下命令，在交互提示中输入新密码（不会回显，也不作为命令行参数保存）：

```sh
docker compose -p longfor-checkin exec checkin python manage.py reset-password 用户名
```

此命令只修改指定普通用户的本站密码，不影响龙湖登录凭证。管理员密码仍由 `.env` 管理。`manage.py import-har` 作为本机管理命令仍只导入管理员空间；普通用户在自己的网页内导入。

### PostgreSQL 开发测试

不设置 `PG_TEST_DSN` 时仅运行 SQLite 等测试，PG 集成测试跳过。设置时必须指向可删除的独立测试数据库，并包含 `public.longfor_test_marker` 中 `id=1,value='isolated-test-only'` 的标记；没有标记会拒绝重置。测试会删除该库中 `checkin_u*` schema，禁止指向正式数据库。真实迁移、序列、连接池隔离、调度器互斥和错误回滚都在 PG 集成测试覆盖。

数据库连接池在所有用户间共用，默认最多 5 个连接；调度器另外保持一个 PostgreSQL advisory lock 会话，阻止不同数据卷启动重复调度器。锁连接丢失时进程退出，由 Docker 重启策略恢复，重启后先查询服务端状态再继续中断任务。仍需单实例部署，不要手动扩容。

实现参考：[Psycopg 连接池](https://www.psycopg.org/psycopg3/docs/advanced/pool.html)、[PostgreSQL 显式锁](https://www.postgresql.org/docs/current/explicit-locking.html)。
