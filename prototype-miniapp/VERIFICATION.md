## 浏览器验证

使用 Playwright 独立浏览器上下文运行 `verify.browser.js`，40 项检查全部通过，包括：

- 首页按开启的账号统计进度，最近记录仅显示五条。
- 预置三个 App、两个小程序实例；再次添加 App 后原实例不被覆盖。
- 账号昵称、签到时间、复核时间与自动开关独立；修改页预填当前配置。
- 新账号校验成功后，需要用户主动确认开启计划；错误文件不创建账号。
- 登录更新失败保留原配置，成功更新保留原计划；App 短信仅为验证码演示，小程序没有不受支持的短信入口。
- 手动签到、状态复核、执行失败和登录失效分别展示；成功后主要操作为查看结果。
- 程序及账号搜索筛选正常；结果详情按实例、日期、状态定位；移除实例保留历史记录。
- 企业微信绑定演示、QQ/163 收件邮箱校验与设置正常；通知失败不改变签到结果，支持失败及成功的重试反馈。
- 首次使用空页面、恢复默认演示、异步按钮加载状态正常。
- 320、375、390、430、768、1440px 下检查主要页面及添加流程，无横向溢出。
- 无浏览器脚本异常；交互测试没有发起外部网络请求。

额外检查：中文昵称搜索保留原输入节点及焦点，避免重新渲染打断输入；页面没有真实文件上传输入；提高说明文字和导航文字对比度；主操作触摸区域至少 44px。

JavaScript 通过 `node --check`；本地静态服务器返回 HTTP 200。已查看手机首页、账号列表、账号详情和桌面预览截图。

## 后续真实接入边界

本次为浏览器中的可点击原型，不是可直接审核发布的微信小程序。时间计划不产生真实定时任务；所有登录、校验、短信、签到、复核及通知均为模拟。企业微信身份关联不能获取第三方龙湖登录状态。

视频按钮需要用户主动点击，才会打开现有平台的公开视频页面；设计参考链接同样只在点击后打开。原型自身无需任何外部资源即可运行。
