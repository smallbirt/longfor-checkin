# 每日签到 · 用户管理与积分原型

独立交互原型，使用虚构用户与浏览器本地数据。未接入生产接口，不修改真实用户、计划或余额。

## 打开方式

在项目目录运行：

```sh
python3 -m http.server 18096 --bind 127.0.0.1 --directory prototype-admin
```

浏览器打开 `http://127.0.0.1:18096`。也可直接打开 `index.html`，若浏览器允许本地存储，修改会保留。底部“恢复示例数据”可重置演示。

## 建议的第一版规则

- 每位新用户默认 2 个免费自动打卡名额。App、小程序合计计算；每个开启自动任务的签到账号占用 1 个。
- 10 积分购买 1 个永久名额，购买时扣一次，不按天或按执行次数扣分。
- 总名额 = 免费名额 + 已购名额；可用名额 = 总名额 − 已占用名额。
- 暂停或移除签到账号释放占用，已购买名额保留，不自动退积分。
- 尚有空余名额时直接启用，不要求再次购买；“扩容”只增加可用容量，不自动添加账号或开启计划。
- 本站用户停用后不能登录、购买名额，自动任务暂停；原来的计划、积分和已购买名额保留。恢复后可继续使用。
- 积分先由管理员发放或扣减，每笔要求原因。余额不可为负；无自动充值、现金价格或退款规则。
- 修改免费名额默认值只影响新用户，修改价格只影响后续购买，避免追溯扣分。
- 管理员可以单独调整用户的免费名额；不能将总名额降到已占用数量以下。
- 新用户免费名额 2 个、额外名额永久有效、积分初始为 0，属于本原型的产品假设，正式接入前可调整。

## 可以体验的流程

1. 用户列表：搜索、状态筛选、排序、分页、批量选择；快捷定位登录失效、签到失败、名额满或积分不足的用户。
2. 管理详情：查看积分、名额、签到账号、通知设置、积分流水和操作记录，保存管理员备注。
3. 积分调整：单人发放 / 扣减、批量发放；积分和流水同步变化，不能超余额扣减。
4. 用户扩容：详情里的“体验用户扩容”展示用户端确认；足额购买扣分并增加名额，不足时明确缺口。
5. 状态管理：停用 / 恢复，模拟退出所有设备、重置本站登录，操作原因记入日志。
6. 权益规则：调整新用户免费名额和购买价格，新旧权益分开应用。
7. 创建演示用户、关闭 / 开放注册、恢复全部示例数据。

## 接入真实后端时的关键约束

- 用户状态与龙湖凭证状态分别存储，登录失效仅影响对应签到账号。
- 管理接口鉴权，积分只允许管理员变动或由服务端扩容扣减，客户端不能提交余额或价格。
- 扣分、增加已购名额、写流水放在同一个数据库事务中，并使用唯一购买单号防止重复扣分。
- 并发开启自动计划时，在同一事务中检查实际占用与可用名额；暂停 / 归档释放占用。
- 管理员变动、购买时间、积分前后余额、操作人、原因、关联用户与购买单号应可追溯。
- 退出登录、一次性重置凭证、停用、恢复均为原型模拟，尚未接入真实鉴权和调度。

## 设计

延续现有白底与绿色导航，列表展示摘要、侧栏展开详细信息；账号状态、龙湖登录、积分余额与名额分别表达。浅色桌面为主，移动端将表格折成用户卡片。SVG 图标、可见焦点、原生弹窗、文本状态、减少动态效果支持，无外部字体和网络资源依赖。
